# IDRC WCAG Reporter - Project Overview

## What is the IDRC WCAG Reporter?

The **IDRC WCAG Reporter** is a specialized tool that transforms accessibility audit findings into professional, standardized reports. It enables auditors and organizations to document and communicate the results of WCAG (Web Content Accessibility Guidelines) compliance testing in a structured, professional format.

The tool converts detailed accessibility findings, documented in a simple markdown-based format, into comprehensive HTML reports and PDF documents that clearly communicate conformance status, issues discovered, and their severity.

## Purpose

The primary purposes of the IDRC WCAG Reporter are to:

1. **Standardize Reporting** - Create consistent, professional accessibility audit reports across organizations and auditors
2. **Streamline Documentation** - Allow auditors to write findings in a simple, maintainable markdown format while automatically generating professional reports
3. **Improve Accessibility Communication** - Present accessibility findings in a clear, structured way that both technical and non-technical stakeholders can understand
4. **Support Compliance** - Help organizations document their accessibility conformance status and plan remediation efforts
5. **Enable Traceability** - Create permanent records of accessibility evaluations linked to specific success criteria and severity levels

## Target Audience

### Primary Users
- **Web Accessibility Auditors** - Professional auditors who conduct WCAG compliance evaluations
- **Quality Assurance Teams** - QA professionals responsible for accessibility testing
- **Digital Service Organizations** - Government and public sector organizations required to report accessibility compliance
- **Accessibility Consultants** - Consultants helping organizations improve digital accessibility

### Secondary Users
- **Project Managers** - Who need clear reports on accessibility status for planning and budgeting
- **Developers** - Who need structured information about accessibility issues to remediate
- **Compliance Officers** - Who need documentation for regulatory compliance (e.g., accessibility statements, DOS-law compliance)
- **Executive Leadership** - Who need high-level summaries of accessibility conformance

## Key Features

### Core Capabilities
1. **Markdown-Based Input** - Auditors document findings in simple markdown files with structured metadata
2. **HTML Report Generation** - Automatically generates professional HTML reports with navigation, tables of contents, and formatted content
3. **PDF Export** - Creates accessible PDF documents (PDF/UA-1 compliant) suitable for distribution and archiving
4. **WCAG Success Criteria Mapping** - Automatically categorizes findings against specific WCAG success criteria
5. **Issue Severity Classification** - Supports severity levels and difficulty classifications for prioritization
6. **Multi-Language Support** - Supports rendering in multiple languages
7. **Metadata Integration** - Captures audit metadata (evaluators, dates, scope, technologies tested, etc.)

### Report Components
- **Audit Summary** - Overview of the evaluation including scope, evaluators, and target compliance level
- **Conformance Statement** - Clear statement of conformance status (compliant, partially compliant, non-compliant)
- **Issue Register** - Comprehensive list of all findings organized by WCAG guideline and severity
- **Scope Definition** - Clear delineation of what was and was not evaluated
- **Testing Summary** - Details of testing tools, browsers, and assistive technologies used
- **Technology Stack Documentation** - List of technologies evaluated (frameworks, libraries, techniques)

## Why It Matters

### For Organizations
- Demonstrates commitment to digital accessibility
- Provides evidence of compliance with accessibility regulations (e.g., DOS-law, ADA, AODA, EN 301 549)
- Creates actionable documentation for developers to fix issues
- Enables accessibility improvement planning and tracking

### For Auditors
- Reduces time spent formatting and organizing audit findings
- Ensures consistent report structure and professional presentation
- Allows focus on the audit itself rather than report generation
- Creates reusable, maintainable documentation

### For Users with Disabilities
- Accessible reports themselves (HTML and PDF/UA-1 compliant)
- Clear communication of accessibility status helps users understand what to expect
- Findings documentation enables remediation that improves actual web accessibility
- Demonstrates organizational commitment to accessibility

## Who Benefits

1. **Web Accessibility Auditors** - More efficient workflow, professional outputs
2. **Organizations Being Audited** - Clear, actionable accessibility improvement plans
3. **Regulatory Bodies** - Consistent documentation of compliance efforts
4. **Users with Disabilities** - Improved accessibility through documented findings and remediation
5. **Development Teams** - Structured, prioritized list of accessibility issues to address
6. **Compliance Teams** - Proper documentation for regulatory and legal requirements
